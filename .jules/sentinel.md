## 2024-05-24 - Exposed GEMINI_API_KEY to Client via Vite Config
**Vulnerability:** The `GEMINI_API_KEY` was fully exposed to the client bundle. The backend API key was injected into the Vite build using the `define` property in `vite.config.ts`, making it accessible via `process.env.API_KEY` in the browser. It was then read directly in `ChatBot.tsx` to instantiate the `GoogleGenAI` client on the frontend.
**Learning:** This existed because a server-side endpoint (Backend-for-Frontend / BFF pattern) was not created to intermediate requests to the Google GenAI service. Exposing API keys in Vite's `define` config makes them trivial to extract, completely compromising the AI service account.
**Prevention:** Always implement a Backend-for-Frontend (BFF) pattern (e.g. Serverless functions, API routes) for API calls that require sensitive secrets. Use environment variables strictly on the server-side, and make clients hit your API endpoints instead. Never expose backend API keys using client-side bundler replacement configurations like Vite's `define` or Webpack's `DefinePlugin`.
