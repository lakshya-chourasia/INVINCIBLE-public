## 2024-05-24 - [Secure Error Handling]
**Vulnerability:** Found an issue where the backend error response was potentially being logged and returned directly to the user in `SubPages.tsx`. Specifically, the `catch (err: any)` block inside `JoinCollective` was using `console.error('Error saving to database:', err);` and `setError(err.message || ...)`, which could leak sensitive database constraints or structure information if Supabase throws a raw error string or unhandled exception.
**Learning:** Supabase errors can contain details about database policies or structures. Passing these directly to the client state and logging them can expose internal information. Also, using `any` for caught errors circumvents type safety.
**Prevention:** Always use `catch (err: unknown)` for type safety, and avoid logging or returning raw error objects to the client. Display a generic, sanitized error message to the user while keeping specific details secure or in server-side logs only.
