## 2024-05-24 - Stop Data Leakage on Database Errors
**Vulnerability:** Information Leakage / CWE-209 - The frontend `JoinCollective` component exposed raw database error payloads (`err.message`) in its `catch` block straight to the user interface via `setError(err.message)`. If the backend (Supabase) returned an internal SQL error, permission denied, or schema details, this would be visible to end users.
**Learning:** This repo's convention of mapping unhandled errors directly to `setError` caused raw API error structures to leak into the UI rather than displaying generic fallback messages. Always hardcode safe, generic fallback errors unless the specific error type is explicitly checked and safe to display.
**Prevention:** Avoid blindly assigning `err.message` in frontend code connecting to backend services or databases. Always catch errors as `unknown` (rather than `any`) to enforce type-checking and manually construct safe error strings or handle specific known error codes safely.
