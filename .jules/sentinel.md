## 2024-05-24 - Prevent Database Error Information Leakage in UI
**Vulnerability:** When handling generic exceptions (`catch (err: any)`) in frontend forms communicating with a backend/database (e.g., Supabase insert in `SubPages.tsx`), the direct usage of `err.message` in the UI error state (`setError(err.message || '...')`) leaks underlying database schema, connection states, or query details to the end-user.
**Learning:** Raw exception objects or stack traces from backend operations bubbling up to the client should never be trusted or rendered directly. The application needs to catch all unknown exceptions and present standardized, generic feedback (e.g. "Synchronization failed") while logging the detailed exception locally. Using `unknown` instead of `any` in catch blocks forces type-checking and helps prevent accidental leakage by making the exception harder to render dynamically without inspection.
**Prevention:** Always cast caught errors as `unknown` in catch blocks (`catch (err: unknown)`), explicitly log the full error via `console.error` for internal telemetry, and update user-facing UI states exclusively with static, generic error strings.
