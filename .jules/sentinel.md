## 2024-04-27 - Information Leakage in Configuration and UI Error Messages
**Vulnerability:** The application was exposing the `VITE_SUPABASE_URL` via `console.log` in production logs within `supabase.ts`. Additionally, the frontend catch block for saving members in `SubPages.tsx` was directly exposing raw database error messages (`err.message`) from Supabase to the end user UI, leaking internal structure or connection issues.
**Learning:** Even though `VITE_` variables are public to the frontend bundle, explicitly logging them unnecessarily clutters production logs and may inadvertently expose environment routing configurations to scraping. Furthermore, piping raw backend error messages directly to the UI without sanitization violates the 'fail securely' principle and can reveal database structures, field names, or auth states to end users.
**Prevention:** Remove unnecessary configuration logging in production builds. In UI catch blocks handling backend responses, strictly log the raw error internally (`console.error`) and display a sanitized, generic fallback error message to the user (e.g., 'Synchronization failed. Please check your credentials.'). Use `catch (err: unknown)` over `catch (err: any)` in TypeScript to enforce type checking via `err instanceof Error` before accessing error properties.
