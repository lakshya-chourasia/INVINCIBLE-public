## 2024-03-08 - Fix Information Leakage in Error Handling and Logs
**Vulnerability:** Raw exception objects containing potentially sensitive backend infrastructure details (like internal connection strings or query paths) were being exposed in frontend `catch` blocks and passed directly to UI components (`setError(err.message)`). The `supabase.ts` initialization file was also logging the database URL directly to the client console on successful initialization, providing unnecessary intelligence on the backend architecture.
**Learning:** Even simple CRUD catch blocks can become vectors for information leakage if typing is left as `any` and default error properties are trusted blindly. Developer-focused console logs in initialization files often accidentally ship to production environments unless explicitly pruned.
**Prevention:** Enforce generic error messaging on all client-facing surfaces. Use `err: unknown` type guards instead of `err: any` in catch blocks to promote safe destructuring. Never log connection URLs or API configurations directly to the client browser console.
