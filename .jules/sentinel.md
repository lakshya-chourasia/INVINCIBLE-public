## 2025-03-09 - Fix Information Leakage in error messages and logs
**Vulnerability:** The application was exposing database configuration details and internal backend errors to the user and console logs. Specifically, `err.message` in the catch block of `JoinCollective` was directly displayed to the user via UI state, and the Supabase API URL was logged out via `console.log` on application init.
**Learning:** Returning unhandled backend error messages to the frontend can unexpectedly expose database structures or internal network details if the API goes down. Logging environment configurations in frontend components might expose sensitive API URLs if error tracking or analytics intercepts `console.log`.
**Prevention:** Always overwrite generic user-facing state variables with static fallback error strings. Never pass raw error objects or error messages directly to the frontend DOM. Never use `console.log` for any configuration details containing URLs or keys on the frontend.
