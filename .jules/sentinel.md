## 2024-05-24 - [Information Disclosure Prevention in Database Error Handling]
**Vulnerability:** The error handling block in `SubPages.tsx` was directly returning `err.message` when a Supabase database insertion failed. This exposed internal database details (potentially including schema names, SQL error codes, or other sensitive details) to the client-facing UI.
**Learning:** Frontend `catch` blocks handling backend/database operations must display generic error messages to the user to prevent information leakage, rather than bubbling up raw exception strings or stack traces. Additionally, the project follows a convention of using `unknown` rather than `any` in `catch` blocks.
**Prevention:** Always use generic fallback messages in the `catch` block state setters (e.g., `setError('Synchronization failed. Please check your credentials and try again.')`) while logging the actual `err` object to the console or an internal logging service. Use `catch (err: unknown)` to enforce stricter typing on error objects.
