## 2025-04-22 - Prevent Layout Thrashing in Throttled Mouse Events
**Learning:** Using `document.elementFromPoint` within high-frequency events like `mousemove` (especially when inside `requestAnimationFrame`) forces synchronous layout recalculations and causes serious performance degradation. Also, defining caching variables for event targets locally inside the event handler instead of the outer scope causes stale closures in scheduled RAF callbacks.
**Action:** Always prefer using `e.target` from the original event to identify interactive elements, rather than checking coordinates. Additionally, when throttling with `requestAnimationFrame`, declare caching variables for the event target (e.g., `let currentTarget: HTMLElement | null = null;`) in the outer scope alongside coordinate variables so the RAF closure always has the latest target even if multiple events fire before the frame executes.
