## 2024-06-18 - Replacing `document.elementFromPoint` with `e.target` in high-frequency event listeners
**Learning:** In high-frequency event listeners like `mousemove` that are throttled with `requestAnimationFrame`, using `document.elementFromPoint(mouseX, mouseY)` forces synchronous layout recalculations up to 60 times per second, leading to layout thrashing. Because global overlays (like custom cursors or noise filters) often have `pointer-events: none` applied, `e.target` can be directly accessed to correctly identify the interactive element beneath the cursor without triggering a layout hit-test.
**Action:** Always prefer capturing `e.target` in the event handler scope (storing it in a variable alongside `mouseX` and `mouseY`) rather than re-computing the element from screen coordinates via `document.elementFromPoint` within the animation frame callback.
