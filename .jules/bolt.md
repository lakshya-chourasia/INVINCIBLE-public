## 2024-05-24 - Closure bug in throttled events
**Learning:** When throttling frequent events (like `mousemove`) with `requestAnimationFrame`, do not calculate state (like checking `e.target.closest()`) outside the `rafId` closure if that calculation depends on the *latest* event data. Storing derived state in an unthrottled local variable and using it in the throttled `requestAnimationFrame` block causes closure staleness. The `requestAnimationFrame` callback will capture the derived state from the *first* event of the frame, but later events before the frame render will overwrite coordinates without updating the captured derived state, leading to desynchronized UI bugs (e.g. stuck hover states).
**Action:** Store the raw event data (like `e.target`) in outer-scoped variables (alongside coordinates like `mouseX/Y`) and perform the derived state calculation *inside* the `requestAnimationFrame` callback using those outer-scoped variables.
