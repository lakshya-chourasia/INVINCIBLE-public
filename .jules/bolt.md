## 2025-02-28 - Avoid Layout Thrashing in `requestAnimationFrame` using `e.target`
**Learning:** Calling `document.elementFromPoint(mouseX, mouseY)` within a high-frequency `requestAnimationFrame` loop forces synchronous layout recalculations (reflows) on every frame. This is a severe performance bottleneck, especially in this codebase where `GlobalInteraction` handles continuous pointer tracking for glowing overlays and cursor rings.
**Action:** When tracking pointer location for visual interaction (e.g. `mousemove`), capture `e.target` directly from the event object into a mutable variable declared outside the rAF closure (e.g. `let hoverTarget`), and use that variable inside the `requestAnimationFrame` callback. This maintains 60fps tracking without forcing layout recalculations.
